## 1. General Conventions

| Parameter | Specification |
|---|---|
| **Base URL** | `/api/v1` |
| **Format** | `Content-Type: application/json; charset=utf-8` (sauf export PDF : `application/pdf`) |
| **Authentication** | Header `Authorization: Bearer <access_token>` on all routes except `/auth/register`, `/auth/login`, `/auth/refresh`, `/auth/forgot-password`, `/auth/reset-password`, `/regions`, `/crops` and `/health`. |
| **Tokens** | JWT access token (60 minutes, proposed) and refresh token (7 days, proposed). |
| **Roles per farm** | `owner` (primary farmer, 1 per farm), `co_farmer` (0 to N), `advisor` (0 to N). |
| **Identifiers** | Prefixed strings : `usr_`, `frm_`, `mbr_`, `pcl_`, `hist_`, `cmp_` (computation), `note_`. |
| **Dates and Times** | ISO 8601 en UTC (ex. `2026-11-14T11:38:00Z`). |
| **Geometry** | GeoJSON, coordinates `[longitude, latitude]`, WGS84. |
| **Region** | Area code, ex. `cm_yaounde`. The list is provided by `GET /regions` ; the server derives the crop file from it (`crops_cm.csv`). |
| **Language** | Header `Accept-Language: fr` (default) or `en` ; the fields `message` are translated. |
| **Pagination** | Long lists : `?limit=20&cursor=...` ; response includes `next_cursor` (`null` at the end of the list). |
| **Traceability** | Each response includes the header `X-Request-ID`, also included in the field `request_id` in error responses. |
| **Version Control** | Mutable resources contain a field `version` (integer). The client sends it back in the header `If-Match` ; a mismatch returns `VERSION_CONFLICT` (409). |
| **Rate Limiting** | `/auth/login` and `/auth/register` : 5 failures within 15 minutes per identifier and address, followed by 429 with `Retry-After`. |

## 2. Roles and Permissions

Permissions depend on the user's role in the farm that owns the resource. A user who is not a member receives `NOT_FARM_MEMBER` (403) ; a member without the required permission receives `FORBIDDEN_ROLE` (403).

| Route | owner | co_farmer | advisor |
|---|---|---|---|

| `POST, PATCH, DELETE /farms/{id}/members...` | Oui | no | no |
| `DELETE /farms/{id}/members/me` (leave) | no (`LAST_OWNER`) | Oui | Oui |

## 3. Error handling

All errors return the same JSON object, including validation errors generated by FastAPI, which are converted to this format. The frontend relies on the field `code` (stable) and displays the field `message` (in French or English depending on `Accept-Language`).

### 3.1 Standard Format

```json
{
  "error": {
    "code": "INVALID_POLYGON",
    "message": "The drawn polygon has a self-intersection or zero area.",
    "details": {},
    "request_id": "req_8f3a21c9"
  }
}
```

| Field | Type | Description |
|---|---|---|
| `code` | string | Stable uppercase business code; used as a translation key and for frontend logic. |
| `message` | string | User-readable text adapted to `Accept-Language`, with no technical details. |
| `details` | object | Useful information: invalid fields, limit values, retry delay, etc. Empty if there is nothing to add. |
| `request_id` | string | Request identifier to share with the team so the incident can be found in the logs. |

### 3.2 HTTP Status Codes Used

| HTTP | Meaning | When | Frontend Response |
|---|---|---|---|
| **200** OK | Success | Read, update, computation | Display; check for any `warnings`. |
| **201** Created | Resource created | Registration, farm, parcel, member, saved strategy | Display the created resource. |
| **204** No Content | Success with no content | Deletion, logout | Refresh the list. |
| **400** Bad Request | Bad request | Unreadable JSON, invalid polygon | Display a message and let the user correct the issue. |
| **401** Unauthorized | Unauthenticated | Missing, expired, or invalid token; incorrect credentials | Refresh the token; otherwise, show the login screen. |
| **403** Forbidden | Insufficient permissions | Unauthorized role, no-member | Display a message; hide the action; reload the dashboard. |
| **404** Not Found | Not found | Unknown farm, parcel, strategy, crop, or region | Display a message; return to the list. |
| **409** Conflict | State conflict | Duplicate, overlap, outdated version, last owner | Display a specific message; reload if `VERSION_CONFLICT`. |
| **422** Unprocessable Entity | Invalid data | Field out of range, incorrect format, business rule violation | Highlight the fields in `details.fields`. |
| **429** Too Many Requests | Too many requests | Repeated login failures | Disable the action for `Retry-After`. |
| **500** Internal Server Error | Internal server error | Unexpected bug | Display a general message with `request_id` ; do not retry automatically. |
| **503** Service Unavailable | Service or data source unavailable | NASA POWER with no cache, engine, or PDF | Display a message; show a “Retry” button; use fallback mode. |

### 3.4 Validation Errors (422)

Validation errors list each invalid field in `details.fields`. The field `path` indicates the location in the request body.

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Some values are invalid.",
    "details": {
      "fields": [
        { "path": "soil.ph", "reason": "out_of_range",
          "message": "Le pH doit être compris entre 3,0 and 10,0.",
          "min": 3.0, "max": 10.0 },
        { "path": "password", "reason": "too_short",
          "message": "At least 8 characters.", "min_length": 8 }
      ]
    },
    "request_id": "req_41b7e0aa"
  }
}
```

Possible values for `reason` : `required`, `too_short`, `too_long`, `out_of_range`, `invalid_format`, `invalid_choice`, `duplicate`, `not_found`.

### 3.5 no-blocking Warnings

Some situations do not warrant an error: the response is successful (200 or 201) and includes a list of `warnings`, which the frontend displays in a banner.

```json
"warnings": [
  { "code": "EXCLUSION_TOO_RESTRICTIVE",
    "message": "Presque All les crops are exclues ; les règles of rotation risquent d'être compromises." },
  { "code": "SRTM_UNAVAILABLE",
    "message": "Altitude and pente indisponibles ; renseignez la pente to la main." }
]
```

| Warning Code | Context |
|---|---|
| `EXCLUSION_TOO_RESTRICTIVE` | Preferences: exclusion of a large part of the catalogue (CU7). |
| `CONSTRAINTS_RELAXED` | Computation: secondary rules relaxed; `details.blocking_constraint` specifies the blocking constraint (CU8). |
| `LOW_CONFIDENCE` | Computation: low confidence; `details.defaults` lists the default parameters (CU8). |
| `SRTM_UNAVAILABLE` | Parcel: elevation and slope are unavailable (CU4). |
| `OUTSIDE_COVERED_REGION` | Parcel: outside the crop catalogue coverage area (CU4). |
| `CENTROID_MOVED` | Boundary update: centroid moved by more than 5 km (CU14). |
| `MARKETS_NOT_PROVIDED` | Preferences: no market outlets specified (CU7). |
| `EXCLUDED_CROP_IN_HISTORY` | Computation: an excluded crop appears in the history (CU7, CU8). |

### 3.6 Fallback Mode and Plan B

External data-source failures must not interrupt the demonstration. The field `data_source_status` in diagnostic and computation responses indicates the data source actually used.

| `data_source_status` | Meaning | Display |
|---|---|---|
| `live` | NASA POWER responded in less than 5 seconds. | No banner. |
| `fallback_cache` | NASA POWER did not respond; the latest cached time series are served (date in `cached_at`). | Banner: “data saved on ...”. |
| `fallback_local` | Neither API nor cache is available; use the regional demonstration fallback dataset. | Warning banner; low confidence. |

If none of the three sources is usable, the error is `CLIMATE_DATA_UNAVAILABLE` (503). A 503 with `ENGINE_UNAVAILABLE` means that the engine is not responding: the frontend keeps the last valid results.

### 3.8 Frontend Rules

- **401 `TOKEN_EXPIRED`** : call `POST /auth/refresh` only once, replay the request ; if it fails, show the login screen with a return to the original page, without losing entered data.
- **403** : do not retry; hide or disable the action for this role; if `NOT_FARM_MEMBER`, reload the farm list.
- **409 `VERSION_CONFLICT`** : reload the resource, display the latest version, and offer the user the option to repeat the change.
- **422** : highlight the fields listed in `details.fields` and display their messages.
- **429** : disable the action for the duration of `Retry-After`.
- **503** : manual retry; for read operations, up to 2 spaced automatic retries (after 1 s and then 3 s). No automatic retries for write operations.
- **500** : display a general message and the `request_id` ; pas of réessai automatique.
- **Network disconnected** (no response) : preserve entered data, display “Unable to connect” and offer a retry; display the cache in read-only mode when available.
- Never display technical traces; always use plain-language messages.
