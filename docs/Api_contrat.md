## 1. General conventions

| Parameter | Specification |
|---|---|
| Base URL | `/api/v1` |
| Format | `Content-Type: application/json; charset=utf-8` (except PDF export: `application/pdf`) |
| Authentication | `Authorization: Bearer <access_token>` header on all routes, except `/auth/register`, `/auth/login`, `/auth/refresh`, `/auth/forgot-password`, `/auth/reset-password`, `/regions`, `/crops` and `/health`. |
| Tokens | JWT access token (60 minutes, proposed) and refresh token (7 days, proposed). |
| Roles per farm | `owner` (main farmer, 1 per farm), `co_farmer` (0 to N), `advisor` (0 to N). |
| Identifiers | Prefixed strings: `usr_`, `frm_`, `mbr_`, `pcl_`, `hist_`, `cmp_` (computation), `note_`. |
| Dates and times | ISO 8601 in UTC (e.g. `2026-11-14T11:38:00Z`). |
| Geometry | GeoJSON, coordinates `[longitude, latitude]`, WGS84. |
| Region | Zone code, e.g. `cm_yaounde`. The list is given by `GET /regions`; the server derives the crops file (`crops_cm.csv`) from it. |
| Language | `Accept-Language: fr` (default) or `en`; `message` fields are translated. |
| Pagination | Long lists: `?limit=20&cursor=...`; response includes `next_cursor` (`null` at end of list). |
| Traceability | Every response contains the `X-Request-ID` header, repeated in the `request_id` field of errors. |
| Version control | Editable resources contain a `version` field (integer). The client sends it back in the `If-Match` header; a mismatch returns `VERSION_CONFLICT` (409). |
| Rate limiting | `/auth/login` and `/auth/register`: 5 failures in 15 minutes per identifier and address, then 429 with `Retry-After`. |

## 2. Roles and permissions

Permissions depend on the user's role in the farm that owns the resource. A user who is not a member receives `NOT_FARM_MEMBER` (403); a member without the right receives `FORBIDDEN_ROLE` (403).

| Route | owner | co_farmer | advisor |
|---|---|---|---|
| `GET /farms`, `/farms/{id}`, `/farms/{id}/members`, `/farms/{id}/parcels` | Yes | Yes | Yes |
| `POST /farms` (create own farm) | Any logged-in user | – | – |
| `PATCH/DELETE /farms/{id}`, `POST /transfer-ownership` | Yes | No | No |
| `POST, PATCH, DELETE /farms/{id}/members...` | Yes | No | No |
| `DELETE /farms/{id}/members/me` (leave) | No (`LAST_OWNER`) | Yes | Yes |
| `POST /parcels`, `PATCH /parcels/{id}` | Yes | Yes | No |
| `DELETE /parcels/{id}` | Yes | No | No |
| `GET /parcels/{id}`, `/climate`, `/local-inputs`, `/history`, `/preferences` | Yes | Yes | Yes |
| `PUT /local-inputs`, `/history`, `/preferences` | Yes | Yes | No |
| `POST /strategies` (computation, simulation, modification) | Yes | Yes | Yes |
| `POST /strategies/save` (keep) | Yes | Yes | No |
| `POST /strategies/saved/{id}/notes` (kind = `observation`) | Yes | Yes | No |
| `POST /strategies/saved/{id}/notes` (kind = `validation`) | No | No | Yes |
| `GET /strategies/saved`, `/saved/{id}`, `/export.pdf` | Yes | Yes | Yes |
| `DELETE` a note | Author or owner | Author | Author |

## 3. Error handling

Every error returns the same JSON object, including validation errors generated by FastAPI, which are converted to this format. The frontend relies on the (stable) `code` field and displays the `message` field (in French or English depending on `Accept-Language`).

### 3.1 Standard format

```json
{
  "error": {
    "code": "INVALID_POLYGON",
    "message": "The drawn polygon has a self-intersection or zero area.",
    "details": {},
    "request_id": "req_8f3a21c9"
  }
}
```

| Field | Type | Description |
|---|---|---|
| `code` | string | Stable uppercase business code; serves as translation key and frontend logic key. |
| `message` | string | User-readable text, adapted to `Accept-Language`, with no technical detail. |
| `details` | object | Useful information: fields in error, limit value, retry delay, etc. Empty if nothing to add. |
| `request_id` | string | Request identifier, to be given to the team to find the incident in the logs. |

### 3.2 HTTP status codes used

| HTTP | Meaning | When | Frontend reaction |
|---|---|---|---|
| 200 OK | Success | Read, update, computation | Display; read any `warnings`. |
| 201 Created | Resource created | Registration, farm, parcel, member, save | Display the created resource. |
| 204 No Content | Success without content | Deletion, logout | Refresh the list. |
| 400 Bad Request | Incorrect request | Unreadable JSON, invalid polygon | Message and correction by the user. |
| 401 Unauthorized | Not authenticated | Missing, expired or invalid token; wrong credentials | Renew the token, otherwise login screen. |
| 403 Forbidden | Insufficient right | Role without permission, non-member | Message; hide the action; reload the dashboard. |
| 404 Not Found | Not found | Unknown farm, parcel, strategy, crop, region | Message; back to the list. |
| 409 Conflict | State conflict | Duplicate, overlap, stale version, last owner | Precise message; reload if `VERSION_CONFLICT`. |
| 422 Unprocessable Entity | Invalid data | Field out of range, incorrect format, business rule | Highlight the fields in `details.fields`. |
| 429 Too Many Requests | Too many requests | Repeated login failures | Disable the action during `Retry-After`. |
| 500 Internal Server Error | Internal error | Unexpected bug | General message with `request_id`; do not retry automatically. |
| 503 Service Unavailable | Service or source unavailable | NASA POWER without cache, engine, PDF | Message; "Retry" button; degraded mode. |

### 3.4 Validation errors (422)

Validation errors list each faulty field in `details.fields`. The `path` field designates the location in the request body.

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Some values are invalid.",
    "details": {
      "fields": [
        { "path": "soil.ph", "reason": "out_of_range", "message": "pH must be between 3.0 and 10.0.",
          "min": 3.0, "max": 10.0 },
        { "path": "password", "reason": "too_short", "message": "At least 8 characters.", "min_length": 8 }
      ]
    },
    "request_id": "req_41b7e0aa"
  }
}
```

Possible `reason` values: `required`, `too_short`, `too_long`, `out_of_range`, `invalid_format`, `invalid_choice`, `duplicate`, `not_found`.

### 3.5 Non-blocking warnings

Some situations do not justify an error: the response is a success (200 or 201) accompanied by a `warnings` list, which the frontend displays as a banner.

```json
"warnings": [
  { "code": "EXCLUSION_TOO_RESTRICTIVE", "message": "Almost all crops are excluded; rotation rules may be compromised." },
  { "code": "SRTM_UNAVAILABLE", "message": "Elevation and slope unavailable; enter the slope manually." }
]
```

| Warning code | Context |
|---|---|
| `EXCLUSION_TOO_RESTRICTIVE` | Preferences: exclusion of a large part of the catalogue (UC7). |
| `CONSTRAINTS_RELAXED` | Computation: secondary rules relaxed; `details.blocking_constraint` specifies the blocking constraint (UC8). |
| `LOW_CONFIDENCE` | Computation: low confidence; `details.defaults` lists the default parameters (UC8). |
| `SRTM_UNAVAILABLE` | Parcel: elevation and slope missing (UC4). |
| `OUTSIDE_COVERED_REGION` | Parcel: outside the crop catalogue zone (UC4). |
| `CENTROID_MOVED` | Outline modification: centroid moved by more than 5 km (UC14). |
| `MARKETS_NOT_PROVIDED` | Preferences: no market outlet provided (UC7). |
| `EXCLUDED_CROP_IN_HISTORY` | Computation: an excluded crop appears in the history (UC7, UC8). |

### 3.6 Degraded mode and Plan B

Failures of external sources must not interrupt the demonstration. The `data_source_status` field of diagnostic and computation responses indicates the source actually used.

| `data_source_status` | Meaning | Display |
|---|---|---|
| `live` | NASA POWER responded in under 5 seconds. | No banner. |
| `fallback_cache` | NASA POWER did not respond; the latest cached series are served (date in `cached_at`). | Banner "data saved on ...". |
| `fallback_local` | Neither API nor cache; regional demonstration fallback dataset. | Warning banner; low confidence. |

If none of the three sources is usable, the error is `CLIMATE_DATA_UNAVAILABLE` (503). A 503 with `ENGINE_UNAVAILABLE` means the engine is not responding: the frontend keeps the last valid results.

### 3.7 Complete examples

**401 – session expired**

```http
HTTP/1.1 401 Unauthorized
```
```json
{ "error": { "code": "TOKEN_EXPIRED", "message": "Your session has expired. Please log in again.",
  "details": {}, "request_id": "req_a01" } }
```

**403 – insufficient right**

```http
HTTP/1.1 403 Forbidden
```
```json
{ "error": { "code": "FORBIDDEN_ROLE", "message": "Your role does not allow this action.",
  "details": { "required_roles": ["owner", "co_farmer"], "your_role": "advisor" }, "request_id": "req_a02" } }
```

**409 – version conflict**

```http
HTTP/1.1 409 Conflict
```
```json
{ "error": { "code": "VERSION_CONFLICT", "message": "This data was modified by someone else.",
  "details": { "current_version": 7, "your_version": 6 }, "request_id": "req_a03" } }
```

**429 – too many attempts**

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 600
```
```json
{ "error": { "code": "TOO_MANY_REQUESTS", "message": "Too many attempts. Try again in a few minutes.",
  "details": { "retry_after_seconds": 600 }, "request_id": "req_a04" } }
```

**503 – climate data unavailable**

```http
HTTP/1.1 503 Service Unavailable
```
```json
{ "error": { "code": "CLIMATE_DATA_UNAVAILABLE", "message": "Climate data is temporarily unavailable.",
  "details": { "retry_after_seconds": 30 }, "request_id": "req_a05" } }
```

### 3.8 Rules for the frontend

- **401 `TOKEN_EXPIRED`:** call `POST /auth/refresh` once, replay the request; on failure, show the login screen with a return to the original page, without losing the user's input.
- **403:** do not retry; hide or disable the action for this role; if `NOT_FARM_MEMBER`, reload the farm list.
- **409 `VERSION_CONFLICT`:** reload the resource, display the up-to-date version and offer to redo the modification.
- **422:** highlight the fields listed in `details.fields` and display their message.
- **429:** disable the action for the `Retry-After` duration.
- **503:** manual retry; for reads, up to 2 automatic retries spaced apart (1 s then 3 s). No automatic retry on writes.
- **500:** general message and display of `request_id`; no automatic retry.
- **Network down (no response):** keep the user's input, display "Connection impossible" and offer to retry; display the cache in read-only mode when it exists.
- Never display a technical trace; always a plain-language message.
